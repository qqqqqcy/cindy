# 空间（Space）与项目归属

空间表示主题或作品，用来收纳多个项目；项目仍表示一个目录，任务仍是一项独立工作。
空间属于侧栏的一级分区，排在设备分区之前，不是「按项目／对话／设备分组」中的一种方式。

## P0：项目收纳

- 一个项目最多属于一个空间。项目下的任务跟随项目显示，不给单条项目任务另设空间归属。
- 显示空间时，已归属的项目只在对应空间出现；置顶保留原有的独立展示。
  没有空间的项目继续留在原设备分区，不新增「未分组」分区。
- 空间可以创建、改名、折叠和删除。空空间保留标题，供后续收纳项目；筛选没有匹配任务时也保留标题。
- 项目可以通过菜单或拖拽加入、切换和移出空间。移出需要确认，随后回到原设备分区。
- 删除空间需要确认，只解除其中项目的归属。空间操作不更改工作目录、文件、任务记录、权限或自动化。
- 顶部的全部任务／本机／某设备是范围，与空间正交。其他设备的项目隐藏，空间标题标注在其他设备的项目数量。
- 项目／对话／设备分组与任务排序继续作用于空间内部和空间外部的内容；空间本身不随任务优先级排序。
- 「显示空间」默认开启。关闭仅取消一级分区呈现，项目按原列表规则显示，保存的空间与归属保留。

## 持久化与边界

空间及项目归属复用 Main 的账号隔离侧栏设置，保存在
`owners/<账号>/sidebar-settings.json`。项目身份复用现有的带来源项目键，归属是单值映射，
不复制项目或任务。旧设置没有空间字段时等同于空空间列表，无需数据库 migration。
删除空间与清理对应归属在一次既有原子设置写入中完成；写入失败不得广播成功。

这些组织信息属于当前 Desktop 的账号偏好；空间可以引用侧栏中来自其他设备的项目，
但本阶段不新增账号级云同步，另一台 Desktop 的空间设置不自动合并。

## 后续阶段与已知缺口

P1 扩展无项目任务、伙伴与群聊引用，以及完整的空间内跨设备组织；伙伴引用不改变其主力电脑、
权限或例行任务。P2 扩展空间内手动排序、项目／伙伴的筛选标签与 `cindy://space` 深链。
标签继续是横切标记，不承担空间归属或分组。

独立的空间多选筛选、搜索条件与结果空间标签、手机空间入口、Agent 空间管理工具和跨端组织信息
同步仍需后续适配；P0 不改变这些入口的现有行为。空间不嵌套，不提供批量删除任务或默认模型／权限。
